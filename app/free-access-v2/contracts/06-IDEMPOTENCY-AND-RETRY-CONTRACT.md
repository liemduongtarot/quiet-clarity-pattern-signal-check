# Execution idempotency and retry contract

POST `/api/executions` with an empty object returns an unguessable random execution capability, signed by a process-ephemeral receipt key, plus expiry. It contains execution ID and issue/expiry bounds only, never quota or identity. No raw PSC input is sent to this endpoint; no quota starts and no product-success count increments. It creates bounded memory state, not a database row or visitor identifier.

POST `/api/readings` carries `{receipt, request:{prompt,context}}` in its body. No bearer identity or idempotency value in URL is accepted. First use binds the receipt to a keyed digest of canonical normalized request in memory. Concurrent same-receipt calls coalesce/reject as in-progress; reuse with changed content fails with fixed collision error. Once a valid result is issued, retries return that result without reexecution, another quota use or another success transition. Only receipt-bound transient state can recover a result. No GET history or cross-session retrieval exists.

Engineering envelope for this synthetic implementation: executor deadline **10 seconds**; a browser transport attempt budget **15 seconds** (10s execution +5s transport/scheduling margin); at most **3 attempts**, separated by **1s and 2s** backoffs. Receipt lifetime is derived as `3 * 15000 + 1000 + 2000 = 48000ms` from issuance, never extended by retries or result reads. This bounds two transient recovery opportunities after a lost response. Logical expiry is checked on every access; a 1s process reaper removes abandoned state without requiring another request. Retained references can therefore exist at most 49s absent event-loop suspension; logical access is denied at 48s. Shutdown clears state. Browser timeout/backoff must match these bounds.

This is the shortest operational envelope selected for the qualified synthetic flow, with necessity stated above; it is not a legal retention period. Real external-provider latency, infrastructure suspension and production retry sizing remain **OPEN — SHORTEST OPERATIONALLY SUFFICIENT PERIOD TO BE QUALIFIED**. No configuration may silently lengthen this specimen's retention.

Input references are discarded after execution/failure; only keyed digest, deadline, in-progress marker and possibly valid result + associated quota outcome remain transiently. No raw-content file, SQLite/WAL row, log or browser storage. Result remains in current browser DOM until pagehide/refresh or next view; the recovery server reference disappears on expiry. Garbage collection releases references but is not a secure-heap-erasure guarantee; host swap/crash-dump policy is separately governed.

Process restart intentionally invalidates prior receipt signatures. Unknown/expired receipts are rejected, not treated as a new request. Recovery across a process crash is unavailable, but no prior capability can silently consume another use. The user may explicitly start a new execution using the browser's current quota; that is a new request and accepted browser-token limitations still apply. Memory-only recovery must never be described as durable crash recovery.

The API checks connection viability and serializes a valid response before issuance. Quota transition is prepared/committed for that single execution before issuing; failure to issue rolls back the unissued transition, preserving zero use. Successful response API issuance fixes the execution result; no DOM acknowledgment. Aggregate counters increment once after successful issuance; aggregate failure does not change the issued quota/result. Replaying against a newer valid quota state must not cause accidental quota regression. Provider execution abort/timeout result is never allowed to commit after the deadline.

Process-wide bounded capacity prevents unbounded receipt allocations without IP/fingerprint/user-rate tracking. Capacity exhaustion is a technical error and consumes zero. No HTTP test-mode knobs or fault fields enter runtime routes; faults in tests are injected at explicit adapter/clock/socket seams only.

A deadline can reject and discard late output, but JavaScript cannot forcibly erase references held by an uncooperative async adapter. The retained mock makes no external call; synthetic delayed adapters only test rejection. Future provider admission requires cooperative abort and independently qualified resource/heap cleanup, not merely Promise.race.
