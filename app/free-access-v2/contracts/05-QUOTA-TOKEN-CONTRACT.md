# Quota-token contract

Canonical allowance: **4 successful valid committed results per first-party quota cycle**. Cycle length is exactly `720 * 60 * 60 * 1000 = 2592000000` milliseconds. The first successful issued result starts it; not visit, start, submit, failed/invalid execution or receipt creation. Fixed expiry equals start +720h, never rolling lookback. At or after expiry, the next success creates a new cycle. No production environment override may change allowance or cycle length.

Browser-held HMAC-SHA-256 signed token logical fields are exactly `version`, `cycle_started_at`, `successful_uses`, `expires_at`, `key_id`, plus signature. Payload version is token schema, not product version. Signature is external to the encoded payload and validated with timing-safe comparison. Strict schema, canonical encoding/field set, finite integer timestamps, exact expiry arithmetic, valid 1–4 count and bounded length are required. Unknown key/schema, extra fields, malformed/edited/future-start tokens fail closed with a fixed error. Expired but correctly signed tokens mean no active cycle. Missing token is no active cycle. No cookie is minted merely on visit/failure.

No visitor ID, nonce for visitor tracking, cycle number, question, result, classification, status, experiment, payment history or behavioral history. The parsed timestamp/count can be temporarily used to enforce quota and compute a coarse exhaustion bucket, then discarded. No token bytes/hash/signature/derivative becomes database or analytics identity.

Production cookie: `__Host-psc_quota`; Secure; HttpOnly; SameSite=Lax; Path=/; no Domain. Expiry/Max-Age cannot extend the logical cycle. Production uses actual TLS; untrusted forwarding headers never establish secure transport. Signing keys are server configuration, at least 32 bytes, not checked-in production defaults. Key ID is a signing-key selector only; retained verification keys need cover still-valid cycles, with no visitor registry.

Local qualification strategy: explicit synthetic-only loopback HTTP mode with separately named `psc_quota_local_synthetic` cookie, HttpOnly, SameSite=Lax, Path=/, no Domain. This cookie is never accepted as production quota. The mode refuses production NODE_ENV and non-loopback host/peer. UI announces synthetic mock processing and asks for no real personal information. Actual HTTPS tests verify production cookie semantics using a TEST-ONLY self-signed fixture; no production TLS/identity service is deployed.

Security boundary: signature prevents undetected editing, not deletion, old-valid-token rollback, replay, incognito, different browsers/devices, or deliberate concurrent-tab bypass. All are accepted bounded leakage. No claim of four results per person, no fingerprint or identity repair. A same-origin Web Lock re-reads quota before execution and reduces accidental tab races; execution receipts prevent same-execution double counting. Browser-lock absence is disclosed and falls back to a page-local busy guard; no persistent locking ID.

Counted event `successful_valid_committed_result` requires accepted request, completed mock execution, validation, committed signed quota transition and successful synchronous issuance of result+quota response. DOM acknowledgment is irrelevant. Before-issuance disconnect/serialization failure consumes zero; after-issuance network loss can retry the same receipt without consuming another use. Database/network/DOM are not a distributed transaction: “issued” means accepted by the server response API, not delivered/rendered. Quota authority is the signed browser token, not analytics. A crash during telemetry may undercount metrics and must not rewrite quota semantics.

Do not count page view, start, partial form, submit alone, validation failure, execution failure/timeout, invalid result, internal retry, duplicate request, refresh, copy or download. Deliver the fourth result while disabling new execution. A fifth new receipt execution with a four-use token is blocked before the executor. Replaying an earlier result must not replace a newer valid cookie with an older count in ordinary operation; deliberate old-token replay remains accepted leakage.

Technical reference: [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) documents Secure/HttpOnly/SameSite and host-prefix requirements. This contract adds purpose restrictions beyond browser cookie security.
